1. 문서 정보

이 문서는 'NOVA 결제관리 프로토타입 AI 프롬프트 v1.1'을 최신 기준으로 삼아 결제 BO 정책을 정리한 것이다. 프로토타입과 같은 HTML 안에 있고, 화면 동작은 이 문서의 규칙을 그대로 따른다.

표기의미프로토타입 처리
확정프롬프트에 결정으로 명시된 정책그대로 구현
제안프롬프트에 없어 기획 기준으로 정한 값구현하되 제안으로 표시
확인필요결정 주체가 따로 있거나 아직 정해지지 않은 정책데모 가정으로 동작시키고 14장에 모음

구현은 단일 HTML 파일(Vanilla JS)이다. 프롬프트는 React + TypeScript + Tailwind를 요구하지만 요청이 HTML 단일 파일이라 그쪽을 따랐다. 목록, 필터, 위저드, 드로어, 모달 단위로 함수를 나눠 두어 React 컴포넌트로 옮길 때 경계를 그대로 쓸 수 있다. API 호출 위치는 코드의 api 객체에 TODO로 모았다.

7. SCREEN 01 결제수단 기준정보 관리

7.1 목록

검색 필터는 PG, 결제수단, MID, 가맹점 용도명, 채널, 사업주체, 운영상태, 키검증, 적용기간 9개다. MID와 용도명은 부분 일치, 적용기간은 MID 유효기간과 하루라도 겹치면 결과에 넣는다. 필터는 '검색'을 눌러야 적용된다. 빠른 필터는 운영상태 3종과 키 미확인·실패, 적용 예정 요율, 만료 임박(30일 이내 제안)이다.

테이블은 PG, 결제수단, MID, 가맹점 용도명, PG 등록 상호, 정산주체, 계약 세부수단, 수수료, 키검증, 운영상태, 유효기간, 사용 중 코너 수, 수정일이다. 수수료 칸에는 현재 요율과 적용 예정 요율을 함께 보여준다. 기본 정렬은 수정일 내림차순, 페이지당 10건이다. 행을 누르면 상세 드로어, 수수료 칸은 수수료 이력 탭, 코너 수는 연결 코너 탭으로 바로 연다.

7.3 상세, 수수료 이력, 상태 변경

MID 정보를 고치면 같은 MID의 다른 계약에도 반영되므로 수정 화면에 영향 계약 수를 표시한다. MID 코드, PG, 결제수단은 식별값이라 수정할 수 없다. 인증키는 '키 변경'을 눌렀을 때만 입력란이 열리고, 바꾸면 저장 전에 다시 확인해야 한다.

적용 시작된 요율은 잠근다. 잠긴 행의 '수정'을 누르면 차단 안내와 함께 같은 값을 채운 신규 이력 입력란이 열린다. 적용 예정 행은 수정과 삭제가 된다. 남는 이력이 0건이 되는 삭제는 막는다.

운영상태 변경은 '이 계약만' 또는 '이 MID의 모든 계약' 범위를 고른다. 목록에서 여러 건을 골라 일괄로도 바꾼다. 코너에서 쓰는 계약을 일시중지·미사용하면 영향 코너와 같은 결제수단의 대체 MID 후보를 안내하고 확인 체크를 받는다.

8. SCREEN 02 결제이력 관리

검색은 결제일 기간, 주문번호, 거래번호, PG, MID, 결제수단, 거래상태, BSS 반영상태다. 기본 기간은 최근 1개월이다. 검색 영역 바로 아래 요약 바에 조회 전체 합계를 보여준다. 결제금액, 취소금액, 순결제금액이고 결제실패는 뺀다. 확정 결과 미확인 건은 금액이 확정되지 않았지만 합계에 넣고 건수를 따로 표시한다. 확인필요

상세 드로어 탭은 주문정보, PG 결제정보, 금액정보, BSS 반영, 거래 이력, 담당자 6개다. 탭 위에 결제 시점 Snapshot(컨테이너, 코너, PG, MID, 결제수단, 요율)을 고정해서 보여준다. 기준정보에서 요율이나 상태를 바꿔도 이 값은 그대로다.

9. SCREEN 03 거래내역 대사 관리

조회 조건은 추출일자, 전달상태, PG, 결제수단, 검색어(요청 ID, 파일명, 요청자)다. 추출 요청은 4단계로 진행한다.

단계내용
1. 추출 조건거래 기간, PG, 결제수단. 기간 종료일은 오늘 이전 제안
2. 대상 확인대상 건수, 결제·취소·순결제 금액, PG별 내역. 결제실패는 대상에서 뺀다
3. 정합성 검증결과 미확인 0건(차단), BSS 반영실패·불일치(경고, 확인 체크 후 진행), 거래번호 중복, 금액 합계, 대상 1건 이상
4. 파일 생성성공 시 다운로드. 실패 시 실패 사유와 재추출 버튼. 성공·실패 모두 요청 이력에 남는다

요청 상세에서 파일 다운로드, 재추출, 기존 조건 복사, 정산 담당자 전달 기록, 수신 확인을 한다. 전달 기록은 생성이 끝난 파일에만, 수신 확인은 전달 기록 뒤에만 된다. 다운로드는 브라우저에서 데모 CSV를 만들고, BSS 전달은 모의 동작으로 표시한다. 확정

10. SCREEN 04 금융수수료 조회

검색은 정산기간(월), PG, MID, 결제수단, 검증상태, 차이 원인이다. 요약 바에 거래건수, 거래금액, 예상수수료, PG 청구수수료, 차액 합계를 둔다. 행은 결제수단 계약 × 정산월 단위다.

예상수수료는 정률이면 거래금액 × 요율, 정액이면 건수 × 정액으로 계산한다. 요율은 거래일 기준 계약 수수료 이력 행을 쓴다. VAT 포함 여부, 반올림 기준, 취소 수수료 처리는 정해지지 않았으므로 계산에 넣지 않고 화면에 확인 필요로 표시한다. 확인필요

상세 드로어는 계산 요약, 계약 수수료 이력, 건별 계산 근거(표본), PG 청구 데이터 비교, 메모와 확인완료로 구성한다. 불일치와 미수신은 메모를 입력해야 확인완료할 수 있다. 확정 차이 원인은 시스템이 추정해 붙이고 운영자가 바꿀 수 있다. 제안
