1. 목적과 범위

주문 코너 그룹은 자주 함께 쓰는 코너를 정해진 순서로 묶어 주문 프로세스에 한 번에 배치하기 위한 객체다. 프로세스마다 같은 코너 묶음을 반복 구성하는 작업을 없애고, 묶음 단위로 버전을 관리해 변경 영향을 통제한다.

이 문서는 코너 그룹의 등록, 수정, 승인, 발행, 폐기 규칙과 코너 노출 조건을 그룹 안에서 다루는 방식을 정의한다. 코너 원본 관리는 주문 코너 관리, 그룹 배치는 주문 프로세스 관리의 범위이며 이 문서에서는 두 화면과 맞닿는 부분만 다룬다.

5. 노출 조건(선행/후행) 정책

5.1 소유 원칙

노출 조건은 코너 원본이 소유한다. 그룹은 조건을 만들거나 고치지 않고, 조건이 그룹 안에서 깨지지 않는지 검증하는 역할만 한다. 조건을 그룹에서 덮어쓰게 하면 같은 코너가 그룹마다 다르게 동작하고, 원본만 보고 노출 여부를 판단할 수 없어 운영 장애 추적이 어려워진다.

코너 조건은 두 종류다. 선행 코너의 선택값을 보는 코너 조건과 주문 유형, 선택 EPC 상품 같은 상품 정보 조건이다. 상품 정보 조건은 그룹 구성과 무관하므로 표시만 하고 검증 대상에서 뺀다.

5.2 조건 상태 판정

그룹 저장 시 멤버마다 코너 조건의 참조 대상이 그룹 안 어디에 있는지 보고 상태를 판정한다.

상태판정 기준처리
그룹 내 충족참조 대상 코너가 그룹 안에 있고, 조건을 쓰는 코너보다 앞에 있고, 노출 상태정상
외부 의존참조 대상 코너가 그룹 밖에 있음저장 허용. 외부 의존 목록에 기록하고 프로세스 배치 시 검증
순서 오류참조 대상 코너가 그룹 안에 있지만 조건을 쓰는 코너보다 뒤에 있음승인 요청 차단
참조 코너 숨김참조 대상 코너가 그룹 안에서 숨김 상태. 선택값이 생기지 않아 조건이 영원히 성립하지 않음승인 요청 차단
상품 정보상품 정보 조건표시만 함
예시 1. 그룹 내 충족CG-PAY-0001 결제 정보 입력
  1. 요금 납부 수단 등록
  2. 결제수단
  3. 결제 증빙 수단 (조건: 결제수단 = 계좌이체)
예시 2. 외부 의존CG-ORD-0004 단말 혜택 선택
  1. 바로 보상 신청 (조건: 가입 방식 선택 = 기기변경)
  2. T 기프트 선택
  3. 티다팩 쿠폰 선택
가입 방식 선택(CN-ORD-0003)이 프로세스에서 이 그룹보다 앞에 있어야 한다.

순서 규칙만 지키면 순환 참조는 구조적으로 생기지 않는다. A가 B보다 앞이면서 B도 A보다 앞인 배치는 존재할 수 없으므로 순환 참조 검사를 따로 두지 않는다.

5.3 그룹은 프로세스 안에서 하나의 블록이다

  1. 그룹 내부 순서는 고정이다. 주문 프로세스 관리에서 그룹 멤버 사이에 다른 코너를 끼워 넣을 수 없다.
  2. 그룹은 저장 시 외부 의존 목록(코너 ID와 조건 값)을 함께 저장한다. 프로세스 관리는 그룹을 배치할 때 이 목록의 코너가 그룹보다 앞에 있는지만 확인한다. 없거나 뒤에 있으면 프로세스 승인 요청을 막는다.
  3. 후행 방향에는 제약이 없다. 그룹 뒤에 오는 코너가 그룹 멤버의 선택값을 조건으로 쓰는 것은 일반 코너 간 관계와 같다.
  4. 프로세스에서 그룹 멤버를 조건 대상으로 쓰는 뒤쪽 코너가 있다면, 그 멤버를 그룹에서 숨기거나 연결 해제하는 그룹 버전은 해당 프로세스에 적용할 수 없다. 적용 판단은 프로세스 관리에서 한다.

5.4 그룹 자체 조건과 그룹 노출 규칙

1차 범위에서는 그룹 단위 노출 조건을 두지 않는다. 같은 효과는 멤버 코너 조건으로 낼 수 있고, 그룹 조건이 생기면 노출 판단이 그룹 조건과 코너 조건의 2단 구조가 되어 운영자가 결과를 예측하기 어렵다. 그룹은 노출 가능한 멤버가 하나 이상이면 보이고, 모든 멤버가 숨김이거나 조건 불충족이면 영역 전체가 FO에서 빠진다.

5.5 조건 변경 시 처리

코너 원본의 조건이 바뀌면 코너 새 버전이 발행된다. 그룹은 참조 버전을 고정하고 있으므로 운영 중인 그룹은 영향을 받지 않는다. 운영자가 그룹 수정 화면에서 최신 버전 적용을 누르는 시점에 5.2 판정을 다시 수행하고, 순서 오류나 참조 코너 숨김이 생기면 승인 요청을 막는다.

6.2 버전 번호

  1. 신규 그룹은 v1.0으로 발행한다.
  2. 수정은 운영 버전의 끝자리를 1 올린다. v1.2 운영 중 수정하면 작업 버전은 v1.3이다.
  3. 작업 버전 번호는 승인 전까지 유지된다. 반려 후 다시 수정해도 번호는 같다.
  4. 발행된 버전은 삭제하거나 덮어쓰지 않는다.

7. 저장·승인·발행

단계처리
임시 저장그룹명만 있으면 저장한다. 검증 규칙은 적용하지 않는다. 이력에 남지 않는다.
승인 요청8장 검증을 수행하고 결과, 변경 내용, 영향 범위를 한 화면에 보여준다. 차단 항목이 있으면 요청 버튼을 노출하지 않는다. 요청 사유는 필수다.
승인작업 버전을 운영 버전으로 발행한다. 기존 운영 버전은 보존한다. 사용 중인 프로세스의 참조 버전은 바꾸지 않는다.
반려작업 버전을 반려 상태로 돌린다. 반려 사유는 필수이며 상세 화면과 이력에 표시한다.
요청 취소요청자가 승인 대기 건을 회수한다. 작업 버전은 임시 저장 상태로 남는다.

9. 삭제·폐기·연결 해제

작업조건결과
멤버 연결 해제그룹 수정 중 언제든 가능그룹에서만 빠지고 코너 원본은 유지된다. 해제한 코너를 조건으로 쓰던 멤버는 외부 의존으로 바뀌고 안내 메시지를 띄운다.
사용 여부 N그룹 수정 후 승인새 프로세스 연결 불가. 기존 프로세스 연결과 노출은 유지된다.
폐기사용 중인 프로세스가 0개상태 폐기, 사용 여부 N. 조회만 가능하고 되돌릴 수 없다. 버전과 이력은 보존한다.
폐기 불가사용 중인 프로세스가 1개 이상연결된 프로세스 목록을 보여주고 주문 프로세스 관리에서 연결 해제를 먼저 하도록 안내한다.
삭제한 번도 발행되지 않은 그룹(임시 저장, 반려)물리 삭제. 발행 이력이 있는 그룹은 삭제할 수 없다.

10. 변경 전파

  1. 코너 원본이 새 버전을 내도 그룹의 참조 버전은 자동으로 바뀌지 않는다. 그룹 상세의 참조 버전 옆에 최신 버전을 표시한다.
  2. 그룹 수정 화면에서 코너별 최신 적용 또는 일괄 적용으로 참조 버전을 올린다. 적용 즉시 5.2 판정과 미리보기를 갱신한다.
  3. 그룹이 새 버전을 발행해도 프로세스의 그룹 참조 버전은 자동으로 바뀌지 않는다. 그룹 상세의 사용 위치에 프로세스별 참조 버전과 최신/이전 버전 여부를 표시한다.
  4. 프로세스별 새 버전 적용은 주문 프로세스 관리에서 검증 후 수행한다.

11. 화면 구성

화면구성
목록검색 조건은 사용 여부, 상태, 검색어(그룹명, 그룹 ID, 포함 코너). 목록 항목은 그룹 ID, 그룹명과 설명, 구성 코너(노출 순서, 숨김은 취소선), 사용 프로세스 수, 운영 버전, 상태(작업 버전 번호 병기), 사용 여부, 최종 수정일, 최종 수정자. 사용 프로세스 수를 누르면 상세의 사용 위치로 이동한다.
상세왼쪽 FO 미리보기, 오른쪽 기본 정보, 구성 코너(배치 ID, 참조 버전, 타이틀, 노출, 노출 조건 상태), 외부 의존 목록, 사용 위치. 운영 버전과 작업 버전이 함께 있으면 상단에서 전환해 본다.
등록/수정상세와 같은 배치. 구성 코너 표에서 드래그 순서 변경, 타이틀 재정의, 노출 선택, 최신 버전 적용, 연결 해제를 한다. 입력 내용은 미리보기에 바로 반영한다. 하단 버튼은 취소, 임시 저장, 승인 요청.
코너 추가 팝업코너 구분, 검색어로 조회. 이미 추가된 코너와 사용 여부 N인 코너는 선택할 수 없다. 추가 시 코너 최신 버전으로 참조한다.
승인 요청 팝업검증 결과(차단/경고), 변경 내용, 영향 범위, 요청 사유 입력.
변경/승인 이력상세의 별도 탭. 8번 이력 항목을 표로 보여준다.
저장하지 않은 입력이 있는 상태에서 목록, 취소를 누르면 확인 팝업을 띄운다. 승인 대기 중에는 수정 버튼을 막고, 다른 운영자의 동시 수정은 작업 버전 1개 원칙으로 차단한다.
